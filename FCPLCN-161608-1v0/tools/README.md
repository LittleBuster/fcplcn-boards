# Инструменты FCPLCN-161608-1v0

`board_paths.py` задаёт имена каталогов и файлов двух плат: `FCPLCN-CPU-08-1v0` и `FCPLCN-RLY-1616-1v0`. Внутренние ключи `Upper`/`Lower`, имена полей CSV/JSON и электрические обозначения сохранены для совместимости инструментов.

При переименовании схемы генератор сохраняет исходный seed UUID `WiFi-Relay-16-Upper`. Он используется только для постоянных UUID, не для файлов или отображаемого имени. Заголовок схемы — `FCPLCN-CPU-08-1v0`, ревизия — `1v0`.

Предыдущие платы, временные снимки и резервные копии удалены при очистке проекта. Аудиторы дельт `audit_*_revision.py` и бюджетный аудит с `--before-root` остаются инструментами исторического сравнения: им нужна отдельно предоставленная исходная копия с текущей структурой имён. Их фиксированные SHA и ранее сохранённые отчёты не подтверждают переименованные файлы автоматически. `collect_srda_final_evidence.py` привязан к исходной SRDA-ревизии и намеренно отклонит более новые источники; для текущего проекта запускать отдельные актуальные проверки. Галерея сохраняет логические параметры `--scenes Upper Lower Stack`, но имена изображений и манифестов используют новые имена плат.

Ревизия DATA8 добавляет U15 ISO1640BDR и два прямых GPIO38/44, заменяет J3 на 10P (DATA1–8, 5V_ISO, GND_ISO). UART0 RX GPIO44 зарезервирован под DATA8; USB Serial/JTAG сохраняется. Бюджет U3 теперь 890 мА, собственная изолированная нагрузка — 55 мА, общий внешний лимит — прежние 120 мА.

Текущая ревизия питания использует три R-78K на FCPLCN-CPU-08-1v0: U3 — 3,3 В / 1 А; U5 и U12 — 3,3 В / 0,5 А. U12 получает защищённые 12 В и питает отдельную `+3V3_RS485`. На FCPLCN-RLY-1616-1v0 после D3 установлен демпфирующий фильтр R12 1 Ом, C8 220 мкФ и C13 100 нФ. Расчёты и ограничения собраны в `EMI-power-review.md`, отчёты `Power-EMI-*` относятся к предшествующей ревизии; актуальность `Validation.json` для DATA8 определяется хешами входных плат.

Старые RS485/R78 отчёты относятся к указанным в них SHA; текущий аудит их не подменяет. Абсолютные пути staging в отчётах отражают место вычисления, а SHA соответствуют поставленным файлам FCPLCN-CPU-08-1v0/FCPLCN-RLY-1616-1v0.

`build_upper_schema.py` воспроизводит FCPLCN-CPU-08-1v0/FCPLCN-CPU-08-1v0.kicad_sch, локальную библиотеку символов и таблицы библиотек. `svg_to_png.swift` использует AppKit на macOS и сохраняет полный лист шириной 4200 пикселей с сохранением пропорций. Сам файл SVG пригоден для просмотра без растеризации.

После экспорта XML обеих плат `python3 tools/export_combined_bom.py` обновляет общую ведомость `BOM-combined.csv` из фактических компонентов. Оба экспортёра BOM учитывают KiCad `exclude_from_bom`: три голые площадки TP нижней платы не считаются покупными деталями. Общая ведомость сохраняет точный MPN, производителя, допуск, мощность, напряжение, диэлектрик и высоту, если они заданы.

`passive_specifications.py` содержит согласованные общие спецификации и явный список 117 компонентов обеих плат. `build_upper_schema.py` использует этот каталог при генерации. `python3 tools/apply_passive_specifications.py` переносит те же свойства в обе схемы и PCB, сохраняя исходный текст вне свойств компонентов; журнал `Passive-unification-application.json` фиксирует изменения и SHA. Повторное применение идемпотентно, но перезаписывает журнал. После изменения каталога пересобрать XML и все три BOM.

`bom_common.py` объединяет разные имена CAD-посадок только при явно заданных `BOMGroup` и `BOMPackage`. Поле `package` содержит закупочный корпус, `cad_footprints` — все реальные имена посадок; электрические параметры и MPN участвуют в ключе группировки. Получено 43 → 29 → 25 групп R/C/RN при прежних 181 корпусе и 148 + 154 = 302 покупных деталях. Последний шаг — десять TDK C3216X7R1V106K160AC, 10 мкФ / 35 В / X7R / 10% / 1206. Полный перечень и ограничения приведены в `ASSEMBLY.md`.

Текущие проверки этой правки: `Passive-unification-source-audit.json` сравнивает источники до/после; `Passive-unification-board-check.json` содержит native-проверку сетей и свойств; отдельные ERC/DRC — `FCPLCN-CPU-08-1v0/Passive-unification-*.json` и `FCPLCN-RLY-1616-1v0/Passive-unification-*.json`. Исторические отчёты предыдущих электрических ревизий сохраняют собственные SHA и не перезаписываются.

Размещение компонентов, дорожки, заливки и 3D-модели находятся в KiCad PCB и локальных библиотеках. Генератор схемы их не изменяет.

Исторические проверки предыдущей ревизии RS485 (не применяются как доказательство текущей SRDA-разводки):

`audit_usb_copper.py --before <старая-PCB> --after <новая-PCB> --output <отчёт.json>` сравнивает реальную USB-медь независимо от UUID и направления сегментов. USB_DP, USB_DP_CPU, USB_DN_CPU, USB_CC1 и USB_CC2 должны совпасть точно. Итоговый gate — `USB_data_and_CC_match_approved_revision`; флаг полного сохранения геометрии при принятом изменении USB_DN равен `false`.

`audit_rs485_revision.py --project-root <новый-проект> --before-root <старый-проект> --output <отчёт.json>` использует ту же USB-проверку. C34 допускает только замену 0805 на 1206 при прежних 100 нФ и RTC_VCC/GND; R9 сохраняет исходные 0805, положение и подключения. Схема, BOM и PCB указывают C34 1206 на B.Cu, X52,00 / Y98,275 мм. FCPLCN-RLY-1616-1v0 и механика стека проверяются отдельно. CAD эти аудиты не записывают.

Минимальные via Ø0,60/0,30 мм используют предельный поясок 0,15 мм. Для меди 35 мкм стандартный поясок завода равен 0,20 мм, стандартные ширина/зазор — 0,175/0,175 мм. USB работает в режиме Full Speed; аудит геометрии не заменяет измерение сигнала и проверку обмена на прототипе.

Для DATA8 `check_board.py` дополнительно сверяет U15, R57–R60, C48–C51, десять контактов J3 и назначение физических площадок U1.31/U1.36. R57 здесь — 4,3 кОм DATA7, а не историческая нулевая перемычка питания. `DATA8-budget-audit.json` сохраняет исторические хеши предшествующей схемы; текущий статический бюджет подтверждается `SRDA-budget-audit.json`; предыдущие `Power-EMI-*` отчёты подтверждают только содержащиеся в них SHA и автоматически не подтверждают расширенную плату. Текущая SRDA-ревизия содержит Upper148/Lower154, всего302 детали. `srda_contract.py` проверяет пять SOIC8 SRDA05-4BTG D1/D2/D3/D4/D6, отсутствие PESD и D5/D7/D10, эксклюзивные плавающие REF1, местную землю REF2 и соединение неиспользуемых IO6/7 D1/D3 с местной землёй. Для десяти FIELD-линий R61–R70 он проверяет 100 Ом1%0805 и pulse-proof MPN, отдельные сети `DATAi_IC_ISO`/`SDA_IC_ISO`/`SCL_IC_ISO`, подтяжки после резисторов и сохранённые USB22R. CPU GPIO и прошивочный профиль DATA8 не меняются. Для D1 разрешён `RelayStack:SOIC8_SRDA_USB_Clearance`; sourceguard отдельно сравнивает его pads/Fab/courtyard/model со стандартным SOIC8, исключая только шелкографию и технические UUID. `check_board.py` вызывает этот контракт; `electrical_audit.py` по умолчанию пишет текущий `iButton-electrical-audit.json`. Старые DATA8/Power-EMI отчёты не перезаписываются. SRDA-проверки схемы/бюджета не означают завершённую трассировку или испытанную ESD/USB-стойкость; native PCB проверки выполнять после её заморозки.

`audit_data8_srda_revision.py --project-root <проект> --before-root <EMI131-копия> --output <отчёт.json>` — отдельный аудит источников131→148. Для C14/C15/C22/R56 заданы точные итоговые позы без смены слоя и геометрии: B(103;83;180°), B(102,7;85,2;180°), B(103,7;88,5;0°), B(98,8;112,75;180°). J7 может сместиться только в F(50,73.0),90° с сохранением всех пяти площадок. Для единственного прямоугольника Edge.Cuts UUID b5b6c61d-a1a5-478f-b558-7a18aac620ae разрешён только конец (136;119,4)→(136;120,4) мм при неизменном начале (47;70,96), остальных свойствах и полной геометрии других объектов: размер FCPLCN-CPU-08-1v0 теперь 89×49,44 мм. Для отдельно разрешённых локальных изменений ETH_MISO_CPU/ETH_INT_N/ESP_BOOT, а также J2-фан-аутов USB_CC1/USB_CC2/USB_VBUS и RS485_DIR и локальных обходов D4/J7 MOD_VBUS/STATUS_LED/RTC_VBAT, а также двух локальных цепей J8 RS485_A/RS485_B использовать `--approved-copper-manifest <SRDA-approved-main-copper.json>`. Формат: `version:1`, `before_upper_pcb_sha256`, `after_upper_pcb_sha256`, `nets`, где ключ каждой сети включает `/`, а запись содержит только полные отсортированные `before_geometry_nm` и `after_geometry_nm` из `audit_power_emi_revision.geometry_counter`. Допускаются только эти двенадцать сетей (десять MAIN и две цепи J8), причём у RS485_DIR может измениться только старый UUID0287098a-df5b-48f4-9500-9c2739a7bd4b; любой другой список или несовпадающий SHA/полная геометрия даёт FAIL. USB CPU-side, EN и все остальные неразрешённые сети остаются неизменными. Сети USB со стороны разъёма, выходы LED и точный список силовых/FIELD-сетей допускают переразводку, но обязательно перечисляются в журнале. `--pcb <scratch>` выполняет лишь предварительную проверку источников и помечает подменённый путь; окончательный запуск выполняется на замороженной stage-плате. PASS этого инструмента не означает DRC/ERC0, связность заливок, допустимые места деталей или готовность к изготовлению.

## TLP2363 inputs

`replace_lower_tlp2363_schematic.py` migrates only the lower input schematic and is idempotent. `audit_tlp2363_revision.py` compares migrated source with the retained pre-change snapshot and checks all schematic/PCB pins. `check_board.py` verifies all 16 input circuits, local bypass capacitors and purchasing properties. Initial layout generators must not be used to overwrite unrelated current CAD.

## Input RC before TLP2363

`add_lower_input_rc_schematic.py` applies the current 16-channel input RC and LED-shunt circuit without regenerating unrelated source. It supports both the preceding TLP2363 version and the intermediate RC version, and is idempotent. The older TLP migration detects this newer circuit and exits without reverting the 1.2 kΩ input resistors.

`audit_input_rc_revision.py` checks current source against a separately retained pre-change snapshot. `check_board.py` verifies the current 251 lower footprints and all input circuits. The preceding TLP-specific audit records remain historical and must not be treated as checks of the newer RC circuit.
